# SPEC.md: The Input Projection Standard

**Version:** 1.0.0 (Frozen)
**Status:** Normative

-----

## Part 1: Canonical Definition

### 1.1 Formal Definition

An **Input Projection** is a finite, declarative specification of a constrained interaction between an agent and a system, whose sole purpose is to incrementally produce a locally valid data value.

### 1.2 The Distinction: Projection vs. Form

  * **Input Projection (The Ice):** The static, immutable specification. It defines the geometry of a valid input space. It is a map.
  * **Form (The Water):** The ephemeral runtime experience generated by an Engine interpreting an Input Projection. It is the journey through the map.

### 1.3 Axioms

1.  **Finite Interaction:** No unbounded loops or recursion.
2.  **Declarativity:** Constraints on outcomes, not procedures.
3.  **Local Validity:** Validation depends only on the value itself, not external state.
4.  **Single Output:** Produces exactly one value. No side effects.

### 1.4 The Litmus Test

A specification is an Input Projection if and only if:

1.  It can be fully validated via static analysis.
2.  It produces exactly one structurally valid data value.
3.  It requires no execution of hidden state to be understood.

## Part 2: The Primitive Set

An Input Projection must be composed of exactly these **five** structural primitives. This set is minimal and complete (Algebraic Data Types).

### 2.1 The Scalar (Atom)

  * **Definition:** Indivisible value (String, Number, Boolean, Null).
  * **Role:** Termination point for traversal.

### 2.2 The Struct (Product Type)

  * **Definition:** Fixed collection of named Projections (Logical AND).
  * **Relations:** A Struct may declare an optional `relations` array of cross-field predicates (see §2.6).
  * **Logic:** Valid iff **all** fields are valid **AND** all declared Relations evaluate to True.

### 2.3 The Union (Sum Type)

  * **Definition:** Value taking exactly one of a finite set of shapes (Logical OR).
  * **Constraint:** Must be discriminated by a scalar value.
  * **Defaults:** A Union may optionally declare a **Default Variant**. If the discriminator is missing, the Default Variant is automatically active.
  * **Logic:** Valid iff the **selected** branch is valid.

### 2.4 The List (Finite Sequence)

  * **Definition:** Finite sequence of a single Projection type.
  * **Constraint:** **Must** declare `maxItems`. Unbounded sequences are forbidden.

### 2.5 The Reference (Opaque Atom)

  * **Definition:** Atomic value pointing to an external concept.
  * **Constraint:** Validates **Key Format** only. Existence checks are forbidden.

### 2.6 The Constraint Layer

Constraints are predicates applied to primitives.

  * **Purity Requirement:** All predicates must be **Pure** (no side effects) and **Total** (must return boolean for any input without crashing).

#### 2.6.1 Scalar Constraints

Scalars support type-specific constraints: `pattern`, `minLength`, `maxLength`, `enum` (strings); `min`, `max`, `multipleOf` (numbers); `enum` (booleans).

#### 2.6.2 Struct Constraints (Relations)

Structs support cross-field validation via an optional `relations` array. Each **Relation** is a declarative predicate comparing two sibling fields.

  * **Locality:** Relations operate only between fields of the same Struct (sibling fields). Cross-struct or nested field references are forbidden.
  * **Relation Object:**
      * `op`: The comparison operator. One of: `eq`, `neq`, `gt`, `lt`, `gte`, `lte`.
      * `left`: Field name of the first operand.
      * `right`: Field name of the second operand.
      * `label`: User-facing error message when the relation fails.

  * **Allowed Operators:**
      | Operator | Meaning                  |
      |----------|--------------------------|
      | `eq`     | left == right            |
      | `neq`    | left != right            |
      | `gt`     | left > right             |
      | `lt`     | left < right             |
      | `gte`    | left >= right            |
      | `lte`    | left <= right            |

  * **Evaluation:** Relations are evaluated only when both operand fields are present and individually valid. A missing or invalid operand does not cause the relation to fail—it is skipped.
  * **Failure Reporting (Normative):** When a relation evaluates to False, the Engine MUST emit an Issue with:
      * `code: "relation_failed"`
      * `message` equal to the Relation’s `label`
      * `projectionPath` / `valuePath` pointing at the Struct node that declared the relation
      * `relatedProjectionPaths`: A list containing the absolute (root-relative) paths to the `left` and `right` operand nodes (deduplicated if `left === right`).
      * `relatedValuePaths`: A list containing the absolute (root-relative) paths to the `left` and `right` operand values (deduplicated if `left === right`).

## Part 3: The Abstract Machine

The Abstract Machine defines the execution model independent of UI.

### 3.1 Machine State

At step $t$, state $S_t = \langle P, V_t, C_t, \Sigma_t \rangle$

  * **P:** Projection (Static).
  * **V:** Partial Value (Immutable Snapshot).
  * **C:** Cursor (Location).
  * **$\Sigma$:** Judgments (Validity).

### 3.2 The Judgment Lattice (Four-State)

Each node has exactly one state:

1.  **Inactive:** Pruned branch (e.g., unselected Union). Ignored by validation.
2.  **Invalid:** Malformed data or constraint violation.
3.  **Incomplete:** Structurally sound but missing required descendants.
4.  **Valid:** Complete and satisfied.

### 3.3 Aggregation Rule (Normative)

For composite nodes (Struct, Union, List):

1.  If any active child is **Invalid** $\to$ Parent is **Invalid**.
2.  Else if any required active child is **Missing/Incomplete** $\to$ Parent is **Incomplete**.
3.  Else $\to$ Parent is **Valid**.

### 3.4 Transitions & Operations

The Engine is a deterministic transducer: $\delta(S_t, a_t) \rightarrow S_{t+1}$.

  * **Actions:** `SetScalar`, `Unset`, `SelectVariant`, `ListAdd`, `ListRemove`, `MoveCursor`.
  * **Normalization:** The engine strictly removes data belonging to Inactive branches (Garbage Collection).

### 3.5 Cursor Authority

  * **Canonical Order:** Depth-First, Left-to-Right. Skips Inactive nodes.
  * **Normativity:** The Engine is the final authority on Cursor position.
  * **Enforcement:** `MoveCursor` requests are rejected or normalized if they target Inactive or non-existent nodes.

-----

## Part 4: The Minimality Theorem

**Statement:** The set `{ Scalar, Struct, Union, List, Reference }` is irreducible.

  * Removing **Scalar** loses termination.
  * Removing **Struct** loses conjunction.
  * Removing **Union** loses disjunction.
  * Removing **List** loses cardinality.
  * Removing **Reference** loses boundary crossing.

Any feature request requiring a new primitive is rejected as a violation of the axioms.
